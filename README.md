# 束线保护信号接入 · 双路径规划 / 接线复勘

两个功能共用同一服务：

- **双路径规划**：录入有向光纤段（段标识、起点、终点、非负整数延迟），经真实
  HTTP 接口求出起点到终点 **两条边互不重复、总延迟最小** 的保护链路；无法形成
  双路时返回最小割的源侧节点集合与全部外出割边作为瓶颈证据。
- **接线复勘**：在双路录入页旁提交**已批准的有向光纤拓扑**与**复勘代号拓扑**
  （两份均保留并行段与非负整数延迟，每份端点 2–11 个、段至多 24 条），并可锁定
  少量已确认的"代号 → 原节点"对应。服务在所有满足锁定的一一映射中求全局结论。

## 算法

### 双路径规划

将每段光纤建模为容量 1、费用为延迟的有向弧，求流量 2 的**最小费用流**
（连续最短路 SSP + Johnson 势函数 + Dijkstra），再分解为两条路径。

- 保证**全局最优**：不是"先求一条最短路再删边"的贪心。贪心在局部最短路
  占用共享光纤时会误判无解；最小费用流会在整体上重选路径组合。
- 节点允许重合，允许并行光纤（同端点多条不同标识的段各占 1 单位容量）。
- 最大流不足 2 时，在残余网络上从起点做可达搜索：可达集合即最小割源侧
  集合，由该集合指向外部的全部原始段即所有外出割边。

### 接线复勘

在**满足锁定关系的节点双射**（复勘代号 → 原节点）上做二次指派优化，
目标按字典序为：

1. 最大化**方向与延迟均相同**的可配对段数（完全匹配段）；
2. 最小化**其余同向可配对段**的延迟绝对差之和（延迟不一致段，即时延录错）；
3. 取"复勘代号排序后的目标节点序列"字典序最小者作为**规范映射**。

**绝不为各段分别匹配后拼接**：每段的对应都由唯一一个节点双射决定。
逐段就近贪心会因先匹配的段占用代号、逼后续段错接而得到非全局最优结论
（验收中有固定反例：诱饵锁死后仅 1 段全匹配，全局为 5 段）。

实现为带回溯剪枝的深度优先搜索：指派增长时即时落定两端均已指派的
有向端点对贡献；乐观上界用"剩余代号 × 未用节点"的最大权匈牙利指派
（边界段同延迟潜力）加内部段延迟重叠；对已批准图在当前固定点下的
交换自同构候选做等价类折叠（避免对称情形阶乘爆炸，11 个全对称端点的
10! 同优映射也即时返回），并据此累计同优映射数与每个代号的必然/可选目标。

配对结果分四类展示：

- **完全匹配段**：方向、延迟都相同；
- **延迟不一致段**：方向相同但延迟不同（疑似时延录错），给出绝对差；
- **未匹配复勘段 / 未匹配已批准段**：无法同向配对（疑似错接/接反或缺段）。

## 一键验收（Compose verify）

```bash
docker compose up --build --abort-on-container-exit --exit-code-from verify verify
# 或： docker compose run --build verify
```

`verify` 服务会依次执行并以退出码报告结果（全过为 0）：

1. 构建检查（字节码编译）；
2. `pytest`：两个求解器（双路含 4000 个随机有向图对全枚举蛮力的对拍；
   复勘含 1500 个随机双射蛮力对拍，校验最优值、规范序列、同优数与可选目标）、
   输入校验、HTTP 接口；
3. API/HTTP 冒烟与业务验收（`verify/acceptance.py`，对真实运行中的服务发请求）：
   - 双路贪心反例必须返回全局最优总延迟 12，并用**独立枚举**复核；
     校验两条路径边互不重复、链路连续、各路径延迟与总延迟均可复算；
   - 共享瓶颈：源侧集合 + 全部外出割边，并用独立最大流确认双路不存在、
     移除割边后路径数为 0；
   - 复勘**对称歧义**（完全二部图 4 个同优映射）：同优映射数、每代号
     必然/可选目标、规范序列字典序最小，全部独立全枚举复核，锁定可消歧；
   - 复勘**局部贪心误配反例**：全局 5 段全匹配而逐段诱饵锁死仅 1 段；
   - 复勘**锁定冲突**、重复段标识、端点集合不相等、未知锁定代号/目标均
     返回 400 且错误定位到具体字段，错误响应不含任何结论；
   - **旧双路规划接口与页面回归**：路径、字段、页面草稿与过期请求防护保持；
   - 负延迟/重复标识/不存在端点/不可达、并行光纤/零延迟、静态页面冒烟。

## 接口

### `POST /api/protected-paths`

```json
{
  "source": "S", "target": "T",
  "segments": [
    {"id": "e1", "from": "S", "to": "A", "delay": 1}
  ]
}
```

- 成功：`{"status":"ok","totalDelay":12,"paths":[{"delay":6,"segments":[...]}, ...]}`
- 无法形成双路：`{"status":"insufficient","cut":{"sourceSet":[...],"edges":[...]}}`
- 输入错误（负延迟/重复标识/端点不存在）或不可达：HTTP 400，
  `errors` 中每项带 `loc`（如 `segments[2].delay`）定位字段。

### `POST /api/recheck`

```json
{
  "approvedSegments": [
    {"id": "a1", "from": "S", "to": "A", "delay": 1}
  ],
  "recheckSegments": [
    {"id": "r1", "from": "p", "to": "q", "delay": 1}
  ],
  "locks": [
    {"code": "q", "target": "A"}
  ]
}
```

- 成功：

```json
{
  "status": "ok",
  "mapping": [{"code": "p", "target": "S"}, ...],
  "certainty": {"p": "fixed"},
  "options": {"p": ["S"]},
  "optimalCount": 1,
  "metrics": {"exactCount": 3, "delayDiffSum": 0},
  "exactPairs": [{"recheck": {...}, "approved": {...}}],
  "delayMismatches": [{"recheck": {...}, "approved": {...}, "diff": 7}],
  "unmatchedRecheck": [...],
  "unmatchedApproved": [...]
}
```

- `certainty` 为每个复勘代号给出 `fixed`（在所有同优映射中目标唯一，必然）
  或 `optional`（可选）；`options[code]` 列出该代号在全部同优映射中的所有目标。
- 输入错误（两份拓扑端点数不等、重复段标识、负延迟、端点/段数超限、
  锁定代号或目标不存在、两个代号锁同一目标等）：HTTP 400，
  `errors` 带 `loc`（如 `locks[1].target`、`recheckSegments[0].delay`），
  响应不含任何结论字段，页面同步清除本次结论。

## 前端行为

- 两个页签共用同一页面：双路径规划保持原有录入与结果；复勘页并排放置
  已批准/复勘两份拓扑录入与锁定表，端点名输入带候选提示。
- 所有结果只来自真实接口；展示规范映射（代号 → 原节点，必然/可选）、
  完全匹配段、延迟不一致段（含可复算绝对差）、两侧未匹配段，以及全部
  同优映射总数。
- 任一功能提交即清除旧结论；请求带单调序号并使用 `AbortController`，
  过期响应不会覆盖新草稿。
