# 束线保护信号接入 · 双路径规划 + 接线复勘

录入有向光纤段（段标识、起点、终点、非负整数延迟），经真实 HTTP 接口求出
起点到终点 **两条边互不重复、总延迟最小** 的保护链路；无法形成双路时返回
最小割的源侧节点集合与全部外出割边作为瓶颈证据。

另有**接线复勘**：现场采集器常以临时代号记录端点，工程师同时提交一份已批准
拓扑与一份复勘拓扑（可锁定少量已确认代号），服务在所有满足锁定的**一一映射**
中整体择优，直接区分**完全匹配 / 延迟录错 / 错接（未匹配段）**，而不是逐段
就近猜测。

## 双路算法

将每段光纤建模为容量 1、费用为延迟的有向弧，求流量 2 的**最小费用流**
（连续最短路 SSP + Johnson 势函数 + Dijkstra），再分解为两条路径。

- 保证**全局最优**：不是"先求一条最短路再删边"的贪心。贪心在局部最短路
  占用共享光纤时会误判无解；最小费用流会在整体上重选路径组合。
- 节点允许重合，允许并行光纤（同端点多条不同标识的段各占 1 单位容量）。
- 最大流不足 2 时，在残余网络上从起点做可达搜索：可达集合即最小割源侧
  集合，由该集合指向外部的全部原始段即所有外出割边。

## 接线复勘算法

在所有满足锁定的复勘代号→原节点**一一映射**中：

1. **先最大化**「方向与延迟均相同」的可配对段数（完全匹配段）；
2. **再最小化**其余「同向但延迟不同」段的延迟绝对差之和（仅延迟录错）；
3. 仍并列时，按复勘代号（字典序）排序后的目标节点序列取**字典序最小**者
   作为稳定呈现的规范映射；同时枚举全部同优映射，报告总数与每个代号的
   **必然/可选**目标。

评估单位是**整张映射**：固定映射后段只可能在同一有向端点对（并行段组）内
配对，组内做整体最大权二分指派（同延迟最优配对可能交叉，不能按延迟排序后
就近拉链）；再对满足锁定的全部映射做带界 DFS（两级乐观上界、子问题记忆化、
孪生节点对称归并），**绝不为各段分别匹配后拼接**。每份拓扑端点 2–11 个、
段数 ≤ 24，允许并行段与零延迟。

## 一键验收（Compose）

接口/求解器验收：

```bash
docker compose up --build --abort-on-container-exit --exit-code-from verify verify
# 或： docker compose run --build verify
```

再加上**页面**验收（jsdom 真实加载运行中服务返回的页面并驱动点击/填表，
结论只来自真实接口；该服务在 `verify` 成功后才启动）：

```bash
docker compose up --build --abort-on-container-exit --exit-code-from verify-web
```

`verify` 服务会依次执行并以退出码报告结果（全过为 0）：

1. 构建检查（字节码编译）；
2. `pytest`：求解器（含 4000 个随机有向图对全枚举蛮力的对拍）、复勘求解器
   （含数百个随机图对逐桶全枚举的对拍、对称歧义、贪心反例、锁定、并行段）、
   输入校验、HTTP 接口；
3. API/HTTP 冒烟与业务验收（`verify/acceptance.py`，对真实运行中的服务发请求）：
   - 双路贪心反例必须返回全局最优总延迟 12，并用**独立枚举**复核；
     校验两条路径边互不重复、链路连续、各路径延迟与总延迟均可复算；
   - 共享瓶颈：源侧集合 + 全部外出割边，并用独立最大流确认双路不存在、
     移除割边后路径数为 0；
   - 负延迟、重复段标识、不存在端点、不可达输入均返回 400 且错误定位到具体字段；
   - 并行光纤/零延迟、静态页面与过期请求防护的冒烟；
   - **复勘对称歧义**：同优映射数、规范映射、每个代号的必然/可选目标，并用
     独立全枚举复核；
   - **复勘局部贪心误配反例**：延迟全相同的结构陷阱，整体择优才得 3 段完全
     匹配，逐段就近只得 1 段；独立枚举确认全局最优与映射唯一性；
   - **锁定**：锁定破除歧义、锁定冲突/未知代号定位报 400 并清除本次结论；
   - **段级分类**：延迟录错（|Δ| 与之和）与错接（两侧未匹配段）；
   - 复勘重复标识、端点集合不相等、负延迟、段数超 24 均定位报 400；
   - 旧双路规划接口与结果回归。

`verify-web` 服务（`verify/page/page_acceptance.mjs`，Node + jsdom）从**页面**
复勘同一组场景：双路回归、对称歧义、贪心误配反例、锁定冲突、编辑即清结论。

## 接口

`POST /api/protected-paths`

```json
{
  "source": "S", "target": "T",
  "segments": [
    {"id": "e1", "from": "S", "to": "A", "delay": 1}
  ]
}
```

- 成功：`{"status":"ok","totalDelay":12,"paths":[{"delay":6,"segments":[...]}, ...]}`
- 无法形成双路：`{"status":"insufficient","cut":{"sourceSet":[...],"edges":[...]}}`
- 输入错误（负延迟/重复标识/端点不存在）或不可达：HTTP 400，
  `errors` 中每项带 `loc`（如 `segments[2].delay`）定位字段。

`POST /api/reconcile`

```json
{
  "approved": [
    {"id": "a1", "from": "A", "to": "B", "delay": 5}
  ],
  "survey": [
    {"id": "f1", "from": "x", "to": "y", "delay": 1}
  ],
  "locks": [
    {"code": "x", "node": "A"}
  ]
}
```

- 每份拓扑端点 2–11、段数 ≤ 24；延迟非负整数；段标识在各自拓扑内唯一。
- 成功返回：
  - `mapping`：按代号排序的规范映射 `[{code,node}]`（同优时字典序最小）；
  - `mappingCount`：全部同优映射数；
  - `certain` / `optional`：每个复勘代号的必然目标 / 全部可选目标；
  - `exactMatches` / `delayMismatches`：完全匹配段 / 同向但延迟不一致段
    （各含两侧段完整信息与 `delayDiff`）；
  - `unmatchedApproved` / `unmatchedSurvey`：两侧未匹配段（错接/多缺）；
  - `exactCount`、`delayCost`（延迟绝对差之和）。
- 无可行锁定（同一原节点锁给多个代号等）、重复标识、端点集合大小不相等、
  负延迟、超规模：HTTP 400，`errors` 带 `loc`（如 `locks[1].node`、
  `survey[2].id`）定位，并清除本次结论（不返回任何映射）。

## 前端行为

- 所有结果只来自真实接口；双路页展示每条链路段标识、逐段延迟、路径延迟与
  可复算的最小总延迟（页面同时显示加法复算式）。
- 复勘页展示规范映射（必然/可选标注）、全部同优映射数、完全匹配段、
  延迟不一致段与两侧未匹配段；同优映射数 > 1 时逐代号列出可选目标。
- 两个功能区各自独立：提交即清除本区旧结论；请求带单调序号并使用
  `AbortController`，过期响应不会覆盖新草稿；任何编辑都使旧结论失效。
